# outputs/

Backend-facing JSON snapshots, regenerated by `../run_pipeline.py` (or
individually by `../scoring.py`, `../cross_feature.py`, `../alert_reasoning.py`).
Do not hand-edit these — they are generated artifacts, not source data.

## `operator_scores.json`

Array of 15 objects (one per operator), the **Operator Performance Score**
— deterministic, formula-based, **not** an ML model and **not** the same
concept as task-prediction `confidence` (see `../BACKEND_HANDOFF.md` §5a
for the distinction).

```json
{
  "operatorId": "OP-01",
  "score": 96,
  "status": "EXCELLENT",
  "componentScores": {
    "safetyCompliance": 36.5,
    "taskPerformance": 29.8,
    "machineUseBehavior": 20.0,
    "trainingStatus": 10
  },
  "contributingFactors": ["..."],
  "sessionsAnalyzed": 34,
  "tasksAnalyzed": 14
}
```

`status` bands: `EXCELLENT` (85-100), `GOOD` (65-84), `NEEDS_ATTENTION`
(40-64), `CRITICAL` (0-39).

## `cross_feature_insights.json`

Array of 15 objects — per-operator cross-feature synthesis. Flags an
operator only when **at least 2 of 3 independent categories** (`safety`,
`behavior`, `task`) are over threshold — see `../thresholds.py` for the
audit note on why these three are kept independent (a single idling event
must not be counted as both a safety signal and a behavior signal).

```json
{
  "operatorId": "OP-06",
  "operatorNeedsAttention": true,
  "signalsFired": ["behavior", "safety"],
  "evidence": {
    "safetyIncidentCount": 2,
    "idlingSessionCount": 25,
    "overrunTaskCount": 0
  },
  "recommendation": "Consider refresher training: Safe and Efficient Machine Operation.",
  "recommendedModuleId": "TH_SAFE_EFFICIENT_OPS",
  "recommendedModuleTitle": "Safe and Efficient Machine Operation"
}
```

Current run: 10 of 15 operators flagged.

## `alert_reasoning.json`

Array of 201 session objects with at least one structured reason — the
"why am I being alerted" data behind each rule-engine trigger, additive to
`CONTRACTS.md`'s existing `message` field (not a replacement). Each entry:
`{alertType, severity, triggered, reason, observedValue, threshold}`.

## Regenerating

```bash
cd data-ml
python3 run_pipeline.py
```

runs the full chain (generate → validate → train → score → synthesize →
reason) and rewrites all three files above.
