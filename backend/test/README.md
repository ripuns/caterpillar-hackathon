# backend/test/

## What

End-to-end test scaffold for the NestJS backend, generated by `nest new`.

## Why

Kept as-is from the Nest CLI scaffold. Not extended with real endpoint tests during this build — time was spent on manual smoke testing (curl against each endpoint, verified against Dev's reference JSON outputs where applicable) rather than an automated e2e suite, given the hackathon time constraint.

## How

`app.e2e-spec.ts` tests only the default scaffold `GET /` route, which predates the `/api/v1` global prefix and the real feature set — running it as-is against the current app would fail on the path. Not fixed or extended, since no automated test run was part of this build's verification process.

## File Responsibilities

- **`app.e2e-spec.ts`** — Nest CLI default e2e test, unmodified.
- **`jest-e2e.json`** — Jest e2e config, unmodified.
